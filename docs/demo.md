# Як подивитися проєкт

Коротка інструкція: що запустити, під ким заходити і куди клікати, щоб побачити кожну можливість — включно з тими, які за замовчуванням не видно.

## 1. Запуск

Найшвидше — через Docker, одна команда піднімає базу і застосунок з даними:

```bash
cp .env.example .env
docker compose up --build
```

Перша збірка займає кілька хвилин, наступні старти — близько десяти секунд. Далі http://localhost:3000.

Якщо хочете правити код і бачити зміни одразу:

```bash
cp .env.example .env
docker compose up -d db     # тільки база
npm install
npx prisma migrate dev
npx prisma db seed
npm run dev
```

## 2. Дані для входу

| Пошта | Пароль | Хто це |
|---|---|---|
| `alice@example.com` | `password123` | Аліса Тест |
| `bob@example.com` | `password123` | Богдан Демо |

Обидва акаунти вже підтверджені й мають бронювання в сіді, тож одразу видно і свої, і чужі. Найцікавіше — зайти під Алісою: у сітці її бронювання будуть акцентні й клікабельні, а Богданові — нейтральні й без жодних дій.

Після сіду в базі 6 кімнат і 10 бронювань: кілька вже минулих (щоб було що показати у вкладці «Минулі») і кілька майбутніх. Дати рахуються від поточного тижня, тому демо не застаріває.

## 3. Маршрут на п'ять хвилин

1. Увійдіть під `alice@example.com`.
2. **Список кімнат** — картки з поверхом і місткістю. Угорі фільтр «Місткість»: натисніть `8+`, лишиться дві кімнати; `12+` — одна; стан фільтра видно в адресному рядку, посилання можна переслати.
3. Відкрийте **Акваріум**. У понеділку поточного тижня побачите два бронювання **впритул** — «Синхронізація команди» 10:00–11:00 (Аліси) і «Дзвінок із клієнтом» 11:00–11:30 (Богдана). Це не помилка, а суть правила перетинів: кінець одного може збігатися з початком іншого. Обидва вже минули, тому дій на них немає навіть у Аліси.
4. **Клікніть по вільній клітинці** — відкриється форма з підставленими кімнатою, датою і часом. Зверніть увагу: у списках часу немає ані 10:15, ані 20:00, ані тривалості понад 4 години — некоректну комбінацію просто не зібрати.
5. Створіть бронювання. Модалка закриється, блок з'явиться в сітці, знизу справа — коротке повідомлення.
6. **Клікніть по щойно створеному бронюванню** — та сама форма в режимі редагування. Спробуйте перенести його на час, зайнятий Богданом (наприклад, «Планування спринту» у вівторок 14:00–16:00 у кімнаті Марс): отримаєте «Цей час уже зайнятий» над формою.
7. **Скасуйте** — з'явиться діалог підтвердження. Після скасування слот одразу вільний.
8. **Мої бронювання** в хедері: вкладки «Майбутні» / «Минулі», кнопки дій лише в майбутніх, клік по рядку відкриває саме той тиждень у сітці.

## 4. Що не видно за замовчуванням

### Чужий часовий пояс

DevTools → ⋮ → More tools → Sensors → Location: оберіть, наприклад, Берлін, і перезавантажте сторінку. Вісь часу стане 08:00–18:00, а над сіткою з'явиться підпис «Час показано у вашому поясі… Офіс працює 09:00–19:00 за Europe/Kyiv». Блоки лишаться на своїх місцях: вони прив'язані до офісного часу.

### Мобільний вигляд

DevTools → перемикач пристроїв → ширина 360px. Замість тижня з'явиться **один день** зі стрілками і смужкою днів, збільшені тач-цілі, а форма бронювання відкриється на весь екран. Між днями працює свайп.

### Підтвердження email

Зареєструйте нового користувача через `/register`. У консолі сервера (там, де `npm run dev`, або `docker compose logs -f app`) з'явиться посилання в рамці. До переходу за ним бронювати не можна — над сторінкою висітиме банер, а спроба забронювати поверне помилку. Перейдіть за посиланням — банер зникне, бронювання запрацює.

### Сповіщення про кінець бронювання

Потрібно, щоб ваше бронювання завершувалося скоро **і** одразу після нього кімнату займав хтось інший. Найпростіше:

```bash
# у .env
NOTIFY_BEFORE_MINUTES=600
```

Перезапустіть сервер, під Алісою створіть бронювання на найближчі години, під Богданом — впритул після нього, і поверніться під Алісу. У хедері з'явиться дзвіночок із лічильником і разове спливне повідомлення. Якщо скасувати будь-яке з двох бронювань, попередження зникне.

### Щотижневі повтори

У формі створення поставте «Повторювати щотижня» і кількість. Входження позначаються значком `↻` у сітці й бейджем «щотижня» у списку. Якщо хоч один тиждень зайнятий, застосунок відмовить і **назве конкретні дати**, не створивши жодного бронювання. Скасування такого бронювання пропонує вибір: «Лише це» чи «Всю серію».

### Заборона на рівні API, а не кнопок

Найпоказовіше — переконатися, що чуже бронювання захищене сервером, а не схованими кнопками:

```bash
curl -s -c bob.txt -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"bob@example.com","password":"password123"}'

# id бронювання Аліси видно у відповіді розкладу кімнати
curl -s -b bob.txt -X DELETE http://localhost:3000/api/bookings/seed-booking-01
# → 403 FORBIDDEN
```

Більше прикладів — у `docs/api-examples.md`.

### Сторінки помилок

Відкрийте неіснуючу адресу (`/nothing-here`) або неіснуючу кімнату (`/rooms/does-not-exist`) — обидві дають 404 у стилі застосунку, друга з хедером і кнопкою повернення.

## 5. Перевірки

```bash
npm test              # 96 юніт-тестів, далі 48 інтеграційних
npm run test:unit     # лише юніт, найшвидше
npm run typecheck
npm run lint
```

Інтеграційні тести піднімають власну базу `meeting_room_booking_test` і окремий сервер на порту 3100 — робоча база не змінюється. Потрібен лише запущений Postgres.

Найцікавіші для перегляду тести: `src/lib/domain/bookingRules.test.ts` (робочі години з переходом на літній час), `src/lib/domain/grid.test.ts` (геометрія сітки в різних поясах), `src/lib/server/bookings.race.test.ts` (два одночасні бронювання одного слота).
